## H. 有效的處置（經驗）
- **直接在 session 裡提示是有效的**（這是用 Claude Code 當介面的價值）：卡在重複被拒絕的 `ls` 迴圈的 Qwen，收到一次程序性提示（接續錯誤是我的、模型目錄的主機位置、不要重複被拒絕的指令、從 blk2 繼續、重跑 validate）後，立刻脫離迴圈，自己修好 blk1 的格式問題，之後約每 10 到 15 分鐘寫出一份對應表。
- **提示檔機制**（`exchange/.nudge.txt`）加上**中斷目前輪次**：可以在方塊之間送提示，session 會保留上下文。
- **分支詢問**（`--resume … --fork-session`、不給工具）：不干擾工作中的 session，就能問進度；缺點是複製的對話記錄會被監看當成新動作。
- **本機代理關 thinking**、**`dontAsk` 加路徑限定規則**：兩者都用實測驗證過才採用。
- **工具輸出的錯誤訊息要告訴 HDL 怎麼改**：C5 的 ERROR 與 HINT 就是這個原則；模型有看到工具的錯誤輸出才有機會自己修。
- 工具檢查必須同時用「別人（第一次運行）的正確檔案」做回歸測試，避免誤報（C5 的誤報就是這樣發現的）。
