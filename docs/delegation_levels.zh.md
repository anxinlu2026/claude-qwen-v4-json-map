# 委派測試分級表

## 架構的工作(表中 ① 到 ⑧)

| 編號 | 架構的工作 |
|---|---|
| ① | 從症狀和讀程式碼提出假設(「哪一級可能出錯」),每個假設標明「只靠讀程式,尚未證實」 |
| ② | 決定檢查順序(上游先查,一次最多兩個假設) |
| ③ | 取得每一級的標準(規格、規則、模型、預期值),建立 RTL 訊號與模型區塊的配對 |
| ④ | 設計觀察方式(訊號、窗口、比對方法、指令) |
| ⑤ | 判讀結果:證明、排除或不能下結論;更新帳本 |
| ⑥ | 診斷根因,決定修法 |
| ⑦ | 寫出修改 |
| ⑧ | 設計確認方式,決定結案、還原或升級(例如要不要請使用者核准設計新增) |
