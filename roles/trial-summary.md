## 2. 技術發現

1. **同模型的讀取錯誤可重現。** A1.3 的 V2 錯誤在 a1r1 與本次第一次都出現（標準把輸出印成 4×4 矩陣，被按列讀成字）。這是模型的穩定偏誤，不是偶發。
2. **退回機制有效。** 只引用 worker 自己的 S4 規則與同例輸入的寫法，沒有給值，worker 即自行修正，並另外用 openssl 交叉確認；修正向下游傳遞：A1.4 直接用正確密文，A1.5 的 V2 對應到測試台的密文。
3. **測試台只有一個比較點。** A1.5 與 A1.1 一致指出：金鑰擴展 44 個字、每輪中間值都沒有被檢查，失敗只能顯示終點錯，不能定位。
4. **本次相對 a1r1 沒有新的設計結論。** 只比較了 A1 基線這一段，沒有進入定位或修繕。

## 4. 哪些適合固化到 Python

固定且機械的操作（每張都重複做）：

- 把案例檔放進 `control/case_N.md`，並以 conversation 編號改寫標頭。
- 等 `request_next_K.md` 出現或 `conv_N.done` 出現，並以 `CONVERSATION COMPLETE` 回覆以結束 conversation。
- 形式檢查：輸出檔存在、必要段落齊全、無 TODO（原 a1_round 已有）。
- 預算帳彙總：每張的秒數、請求數、結束時 `inputTokens`、累計 conversation 數與秒數（來源已固定）。
- 把交付、回報、reasoning、原始 log、決策日誌複製到 `records/`（`runs/` 被忽略，使用者看不到）。
- 結束時寫 `finish`、`--close`、確認模型卸載。

## 5. 哪些仍需 Claude 判斷

- 內容正確性：對照標準文字檔、模型原始碼與測試台，找出 V2 這類事實錯誤。形式檢查不可能抓到。

- 預算與停止決策：是否續接、重做、停止，由使用者在停點決定。
