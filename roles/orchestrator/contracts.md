# 工單與交付紀錄草案

Claude 決定派工、審查與流程，Python 保存。以下是試走用的紀錄內容，不是正式 schema、狀態機或自動驗收框架；格式先用可讀文字。

## 任務紀錄

使用者目標、題目與階段範圍、模式、模型與設定、可修改範圍、不可取得的資料、驗收、總預算與授權來源。範圍與上限見 [../trial-plan.md](../trial-plan.md)。

## 每張工單

| 內容 | 說明 |
|---|---|
| 識別與角色 | 工單 ID、architecture 或 HDL、角色文件與 skill |
| 目標 | 本張成果與用途 |
| 輸入 | 規格、交付、證據及其版本；必要時行號與 hash |
| 工具與範圍 | 允許操作、可修改檔案、不可取得的資料 |
| 輸出與完成條件 | 產物位置、證據、如何判斷完成 |
| 預算與停止 | 本張時間與輪次上限；未完成時保存的內容 |
| Budget 帳引用 | 派工前的累計用量與剩餘（見 context-budget.md） |
| Session 選擇 | 預設 new；resume 的機制已驗證但工具尚未接入，接入並經使用者同意後才使用，附 ID 與理由 |
| 外部資料與交接 | 容器外保存位置、掛載對應、交接檔 |
| 停點狀態 | 已報告、使用者決定、時間 |

## Worker 交付

結尾固定一份短摘要，其餘作為檔案：

- 摘要：結論、支持範圍、不能推出的結論、證據路徑。
- 原始證據：命令、版本、輸入、原始 log，只列路徑。
- 未完成時：已完成、未完成、繼續所需的操作／資料／資源、部分產物位置。

被硬中止而無摘要時，Python 保存已有資料，Claude 從產物與 log 核對；成果可讀就不要求重新生成。

## 交接檔

交接檔是已接受的交付加原始證據路徑，由 worker 依契約在結尾產出。Claude 不改寫；需要補充時作為獨立附註並標明是 Claude 的判斷。

## Python 保存與回傳

保存實際工單、請求與回答、容器外位置、產物、原始 log、可取得的 usage、起訖時間與中止原因；不記錄憑證；不可得標 unknown。現有工具已寫 `conv_N.done`、`console.log`、`finished.json`，usage 在 `qwen-home/.qwen/usage/`。

回傳結果區分：正常完成、timeout、工具／API／環境錯誤。預算累計由 Claude 在停點彙總，不由 Python 維護。

## 審查紀錄

每張一筆：接受、退回、補件、升級或停止，附原因與引用。交付完成與設計 PASS 分開表示。

形式檢查（原 A1.6 機械閘門）列入每次審查：輸出檔存在、要求段落齊全、無 TODO。這三項不通過時不得接受。
